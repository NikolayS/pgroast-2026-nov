## The proposal, restated

**Problem.** With pg_temp listed after another schema in search_path, create temp table ... (like src including comments) applies the copied comments to a same-named table in the earlier schema. It overwrites that table's column comment, or fails with "constraint ... does not exist". Any user who puts pg_temp late in search_path is affected.

**Proposed design.** transformCreateStmt() already schema-qualifies the target name for permanent tables so that the commands generated after creation find the right table. The patch qualifies temp table names too, using the actual temp schema name (pg_temp_N), so the generated CommentStmts no longer depend on search_path.

**User-visible surface.**
- Behaviour change: copied comments now land on the new temp table, and the command no longer fails when the other table lacks a matching constraint.

**What the author claims.**
- The CommentStmts from like ... including comments name the table by a name list, which loses relpersistence.
- The fix applies to both column and constraint comments.
- The patch targets stable branches as a bug fix.

**Thread state.** Junwang Zhao, Koshi Shibagaki, Salma El-Sayed and João Rito reviewed or tested; v2 adds the constraint test Salma asked for. Koshi raised a concurrent temp schema rename that now errors; he and Jim agreed it needs no handling because it requires a superuser.
